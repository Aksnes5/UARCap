## 训练预算、冻结验证和无检索缺口

MSR-VTT checkpoint 训练预算为 7，MSVD 为 3。MSVD 的 k=1 vs k=3 提供训练范围内的独立外部验证，k=7 相对训练设定是外推。test2690 自原测试排除试验用 300 条，且不是专门为 source holdout 重新构建的数据集。两者复算都支持 external 预算反差。B 测试单元格是 in-domain 参照，不是匹配的 k=0。POST_FIX 缺少同帧、同 checkpoint、同提示骨架、只关闭检索的 k=0，因此所有“外部检索优于无检索”的结论待证。前作的 Video-LLaMA baseline 和旧框架的 k=0 不能拼作匹配反事实。

Adaptive 是 raw X-CLIP 序列的 adjacent gap 出 k，实际喂入 D prefix。规则本身无需拟合，不等于方法选择没有用验证集。路由部署判断来自存在帧缺陷的 PRE_FIX 验证；修复后点估计多数偏 k=1。test2690 的 Adaptive 高于 D3 约 0.59（接近显著阈值），低于 D1 约 0.54 且区间跨零。MSVD Adaptive 比 D1 低 4.46（聚类区间 [−7.68,−1.47]），不能主张优于最佳固定预算、与最佳预算等价或以此作为算法创新。

## 输出行为与数据风险

另以冻结输出和实际 top-k 文本重算三元组匹配。test2690 D1→D7 平均词数 7.92→8.75，与供应文本并集匹配 .142→.334；与固定 top1 的匹配也 .142→.190，故单纯可匹配集合增大无法解释全部观察。POST_FIX val497 也有 8.01→8.65、并集 .147→.331。MSVD 长度 6.77→7.61 可复算；MSVD cap 在冻结 Git/ZIP 缺失，复制比例保留为旧审计报告值，独立标记 `UNVERIFIED`。更长描述、相同短语来源和 CIDEr/SPICE 的不同方向没有识别因果；SPICE 上升不能证明视频语义正确，未独立重跑 SPICE。

六个 manifest 本地逐行验证，无重复 clip ID，全链嵌套。FULL 有 1,091,712 clips 和 345,437 个源，10K–100K 是一个 clip 对一个源，从 250K 开始源重复，因此改变库规模也改变每来源采样。对公开 MSR-VTT 全 10,000 个 source ID 匹配，各 split 精确源交集均为 0。单独查同源、近似文本、视觉哈希只能覆盖所检验的污染，无法排除转传、时序重编码、同场景或模型预训练暴露。`make_external_retrieval_val_scale.py` 用 brief 字符串分组，选该组按 clip ID 排序的第一条嵌入为代表整组；规模的 clips 数不等于可检索的 caption groups 数。归档区分 812,932 manifest 计算的 groups 和 812,014 另行归一的字符串计数，完整原始 caption CSV/生产 embedding/index 清单未提供，不能独立证明两个计数的精确转换规则或生产索引行数。正式正文主报已直接验证的 clips 分母并移交差异至复现附录。VideoUFO brief 描述为机器生成的外部元数据，缺乏同标准的人类核验。这既是实际部署设置，也是源效应解释的混杂。
