# E3 中性条件修复和版本迁移

原 159 个 machine-approved 候选的 `neutral_text` 均为空。旧 Video-LLaMA 的 159 条 Neu 使用同一图书馆阅读短语。将该臂以及旧版包含该臂的正式配对对照排除。交付中的 Qwen 正式 E3 有 636 次缺中性文本错误、0 条预测。旧 Base、Sup、Con 仅在本版候选继续合格且逐条证据、视觉、解码、checkpoint 和模板指纹一致时进入 V2。新目录不存在旧 Neu 合并路径。

## 入选规则

1. 用官方 VideoUFO `clip_id / source_id` 列、VidHalluc 文件名、冻结试点排除集和公开 MSR-VTT 映射核查来源。对已有 159 人工未核验候选，VideoUFO 和 pilot 重叠为 0，已发现两个历史 MSR-VTT 来源重叠，限定可考虑的旧候选至 157。CaReBench 的来源限定到匿名父视频分组。
2. 固定英文活动短语池按查询与字符串内容的 SHA 排序。候选由模板适配到 VidHalluc 活动短语或 CaReBench 完整句。Vicuna 与 Qwen 本地真实 tokenizer 独立计数，每种 tokenizer 的臂间最大差为 3。最多保留四个同时通过长度检查的候选。Gemma 检查句式、自然性、两个目标的区别及蕴含、否定、预设。保留实际回复。
3. 对每个命题分别询问视觉判断。请求仅包含该命题和图像。先核验生成所用 16 帧，再用独立 CPU 解码的 64 个时点核验。分别保存原始回复、证据帧、时间戳、图像摘要、解析状态和不确定性。64 帧给出更密集的视觉代理，对短暂或遗漏事件仍需完整视频人工核验。
4. 修复版本要求目标事实获视觉支持且原 16 帧可见，冲突事实须有可举证的不相容信息，中性命题须同时通过语义筛查并有非目标内容的正面视觉支持。对目标无关与和视频相容分别判断。少于 150 个 VidHalluc 或 30 个 CaReBench Bridge 候选时，保留排除原因并锁住该分支。两条重叠候选不补入替代视频。Bridge 的 f− 必须可回链真实 D 列表的秩、字幕和 clip IDs。
5. 用新 V2 JSON 和新输出目录。V2 上的 Base 持续留空，Sup/Con/Neu 在同一个插入槽各提供一条文本，使用相同视觉路径和解码参数。Bridge 运行零外部视觉的文本注入，只用于这些自然来源冲突的受控文本诊断。正式推断保持人工未验证状态。
6. 双评价器逐目标独立编码 affirmed、negated、vague、absent、unverifiable。解释以实际表达为依据，显式否定不支持肯定表达。缺失及解析不合法保留空值。汇总只对完整四臂和同视频配对。每条尝试绑定模型、查询、臂、评价器、目标和整个生成输入版本。
